## CyberGym 69.0%

在 [CyberGym](https://www.cybergym.io/cybergym/) 上，Whitzard（白泽）在 **1,507** 个真实世界漏洞任务中复现了 **1,040** 个，**pass@1 成功率 69.0%**——而驱动它的，是一个**开源权重**基座模型 **GLM-5.1-FP8**，每个任务的时间预算为 2.5 小时。

CyberGym 是当前公开的、面向进攻性安全智能体最严苛的基准：1,507 个真实漏洞，覆盖 188 个开源项目；每个任务只给智能体一段自然语言描述和一份代码库，要求它凭此构造出能触发该漏洞的概念验证（PoC）输入。Whitzard 用一个权重完全公开的模型达到了这个成绩——能力不在模型本身，而在模型之外的这套系统。

> 传说中，白泽通晓天下万物之情，知世间一切鬼神之名。它不靠猜，它认得。我们以它命名，是有理由的。

## Whitzard 是什么

Whitzard 不是一句提示词，也不是一个通用的写码循环，而是一个**以证据驱动（evidence-driven）的单体安全智能体**，外面包裹着一套为漫长、无人介入的调查而生的运行时：它读懂陌生代码，对它"为什么会崩"形成假设，构造出能证明这一点的输入，并确认崩溃——全程在规定的时间预算内、无人在环。

让它跑得起来的几个想法：

- **只认证据，不靠猜。** 判定一个任务被解出的，有且只有一件事：来自唯一提交通道的、经校验的崩溃。源码、shell 输出、调试器记录、乃至模型自己的信心，都只是诊断证据——而非结论。
- **高密度的 agent–computer 接口。** 智能体能调用的每个工具都返回两份同步视图：一份给机器的 typed 结果，一份给模型的、确定性的摘要"卡片"。模型在干净、可比较的观察之上推理，并始终清楚一个否定结果是"已查完"还是"只是被截断"。
- **面向状态，而非对话。** 模型面对的是一份紧凑、始终最新的决策上下文——持久的计划、一份实时的任务清单、以及绑定到精确源码区间的证据笔记——每一轮都从状态重建，而不是一段无限膨胀的对话。
- **根因计划。** 每个计划都携带可疑漏洞的汇点、路径、载体、门限与机制，以及它尚未确定的"命名未知量"，并随证据积累不断被打磨。分析先行，然后才写下第一个字节。
- **结构化调试。** 当静态推理走到尽头，智能体会在受控容器里进入一个原始调试器直接观察目标，而不是蒙着眼睛反复试。
- **为长任务而生的运行时。** 上下文压力被当作可恢复的条件，而非失败：陈旧的历史被驱逐，而计划、任务与推理状态被保留下来，让一场两小时的调查直到最后一分钟仍然连贯。

以上是与 CyberGym 最相关的部分，但**并非系统能力的完整清单**。

## 一间干净的房间

Whitzard 解每一道题的方式，和一个人类研究员被迫采用的方式一样：只依据眼前的代码。每个任务都运行在各自独占、无网络的临时容器里；评测方私有信息与修复版 oracle 信息，被完全隔离在模型的环境之外。它不查 CVE 库、不反解基准标识、也不读隐藏的参考漏洞利用。在这样的约束下拿到 69.0%，说明的是能力，而不是对测试集的熟悉。

## 实验设置

- **基准：** CyberGym 全集——1,507 个真实世界漏洞任务，覆盖 188 个项目。
- **任务输入：** 公开的漏洞描述、漏洞版代码库，以及公开的 harness / 二进制 / 语料。任何评测方私有信息都不进入智能体。
- **基座模型：** GLM-5.1-FP8——开源权重，自建部署。
- **预算：** 每任务至多 2.5 小时墙钟时间，每任务单次运行（pass@1）；一旦 oracle 确认触发崩溃即结束。
- **评分：** 由 CyberGym 官方 oracle 判定——解出即提交的 PoC 触发了漏洞版目标。

| 指标 | 数值 |
|---|---|
| 复现任务数 | **1,040 / 1,507** |
| 成功率（pass@1） | **69.0%** |
| 基座模型 | GLM-5.1-FP8（开源权重） |
| 每任务预算 | 2.5 小时 |

## 为什么这件事重要

榜单顶端是体量最大的闭源前沿模型。Whitzard 用一个开源权重模型拿下了基准的三分之二以上——这意味着这段距离不是靠更大的模型补上的，而是靠**系统设计**：问题如何被拆解、智能体被允许看到什么、证据如何在一场漫长的调查中被传递、以及构造过程如何被约束在一个唯一而诚实的 oracle 上。

一个有能力的基座模型跑在通用循环里，和同一个模型跑在一套专为安全打造的系统里——两者之间的这道差距，正是全部要点所在。它也恰恰是无法被塞进榜单某一行里的那部分。
